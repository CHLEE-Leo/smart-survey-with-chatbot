## 1. 핵심 연구 질문

> 제한된 질문 유형 안에서, 대화 맥락에 따라 새 질문과 재질문을 선택하는 정책이
> 필요한 판단 근거를 적은 부담으로 정확하게 확보할 수 있는가?

질문 종류 7개는 정보의 주제를 정의한다. 문장을 일곱 번 출력하는 고정 작업이 아니다.
같은 유형도 현재 기록에 따라 최초 질문, 구체화, 의미 확인, 모순 해소로 실현될 수 있다.
정책은 질문 주제를 고르고, 생성 LLM은 그 주제 안에서 실제 발화를 만든다.

우선순위가 높은 연구 질문은 다음과 같다.

- RQ1: 재질문 허용이 불확실·상충된 응답의 정확한 해석에 도움이 되는가?
- RQ2: 응답 형식이 선택지형/개방형일 때 재질문의 가치가 어떻게 달라지는가?
- RQ3: 원문 대화 이력을 직접 읽는 LLM 정책이 구조화 특징 기반 정책보다 유용한 순서를 학습하는가?
- RQ4: 같은 기반 LLM을 정책과 질문 생성에 공유할 때 어떤 파라미터 공유 방식이 안정적인가?
- RQ5: 공개 대화로 계산한 내부 판정과 종료 시 보상만으로 효율적인 문진 정책을 학습할 수 있는가?

## 2. 재질문을 독립적인 연구 주제로 삼는 이유

### 2.1 방문한 문항과 확보한 정보는 다르다

E-3을 이미 물었더라도 “조금 있다가요”라는 응답만 받으면 반응 시간은 불확실하다.
반대로 E-2에 “계란찜을 먹고 20분 뒤 입술이 부었어요”라고 답하면 증상과 시간을 동시에 알 수 있다.

따라서 다음을 구분한다.

- action을 선택했는가?
- 실제 질문이 해당 유형의 의미를 지켰는가?
- 사용자가 어떤 정보를 제공했는가?
- 그 정보가 판단에 충분히 명확한가?
- 다시 물으면 불확실성을 줄일 가능성이 있는가?

질문 방문 여부만으로 action을 제거하면 확인이 필요한 정보를 그대로 남길 수 있다.

### 2.2 유용한 재질문의 종류

| 종류 | 예 | 얻고자 하는 정보 |
|---|---|---|
| 구체화 | “조금 있다가”라고 한 시간 범위를 다시 확인 | 시간 불확실성 |
| 의미 확인 | 보호자가 말한 “검사”가 무엇이었는지 확인 | 검사 종류와 결과의 혼동 |
| 사건 구분 | 피부 반응과 호흡기 반응이 같은 날의 같은 섭취에서 발생했는지 확인 | 서로 다른 사건의 잘못된 결합 방지 |
| 상태 구분 | “요즘 괜찮다”가 회피 때문인지 문제없이 먹어서인지 확인 | 현재 회피와 내성의 혼동 |
| 상충 해소 | 이전에는 제한 중, 이후에는 먹는다고 했을 때 조리형태·시점 확인 | 기록의 모순과 조건 차이 |

행동 예시는 `E-2 → E-3 → E-3 → E-6`이다. 연속된 E-3도 서로 다른 정보를 확인할 수 있다.
재질문 여부는 현재 action과 직전 action의 동일성만으로 정의하지 않고,
이미 다룬 유형을 다시 선택했는지와 실제 질문의 목적을 함께 기록한다.

다만 재질문은 매번 이로운 행동이 아니다.
기억나지 않는 일을 계속 묻거나, 원하는 답이 나올 때까지 묻거나, 같은 답을 반복 요구하는 행동은 비용이 된다.
정책이 배울 것은 **추가 확인의 기대 가치가 그 부담보다 큰 상황**이다.
같은 action 재선택 자체에는 일괄 벌점을 주지 않는다.

### 2.3 선행 근거와 이번 연구의 차이

Conrad와 Schober의 대화형 조사 연구는 비전형적 상황에서 개념을 명료화하는 대화가
응답 정확도를 높일 수 있지만 조사 시간을 늘릴 수 있다고 보고했다.
이는 재질문의 가치와 비용을 함께 검증할 근거다. 한국 식품알레르기 LLM 문진에서의 효과를 입증한 연구는 아니다.
[Conversational Interviewing and Data Quality](https://www.bls.gov/osmr/research-papers/1999/st990250.htm)

따라서 “재질문이 가능하다” 자체를 새로운 발견으로 주장하지 않는다.
이 프로젝트가 검증할 수 있는 기여는 **식품별 문진에서 제한된 7개 행동으로
언제 재질문할지 학습하고, 정확성·불확실성·사용자 부담의 균형을 측정하는 것**이다.
학술적 신규성의 최종 판단에는 별도의 관련 연구 검토가 필요하다.

## 3. 네 가지 시간 선택지와 개방형 질문 비교

원문의 E-3 선택지는 다음과 같다. 사용자 메시지의 “3분–2시간”은 원문에 따라 “30분–2시간”으로 해석했다.

1. 30분 미만
2. 30분 이상–2시간 미만
3. 2시간 이상–4시간 미만
4. 4시간 이상

정확히 30분, 2시간, 4시간인 응답은 각각 다음 구간에 포함된다.
“기억나지 않음”은 별도 응답 상태로 보존하며, 개방형과 선택지형 모두에서 허용한다.

### 3.1 개방형 + 재질문의 잠재적 강점

| 가설 | 설명 | 평가할 상황 |
|---|---|---|
| 범주화 부담 감소 | 보호자가 직접 의학적·시간 범주로 바꾸지 않고 경험을 설명 | 범주 의미를 오해하는 경우 |
| 범주보다 풍부한 정보 | 시간 범위, 기억의 정도, 반응 사건의 순서가 드러남 | “처음에는 입만, 나중에는 몸에도” 같은 응답 |
| 복수 정보 획득 | 한 답변에 형태·증상·시간 등이 함께 포함 | 자연스러운 자발적 정보 제공 |
| 맞지 않는 선택의 발견 | 선택지 하나를 고르기 어려운 이유를 기록 | 다른 사건, 여러 조리형태, 복합 증상 |
| 맞춤 확인 | 사용자가 기억하는 사건·시각을 중심으로 확인 | 분 단위 기억은 없지만 시간 기준점이 있는 경우 |

이들은 **검증할 가설**이다. 자유응답이 자동으로 더 정확한 기록을 만들지는 않는다.
LLM의 추출 오류, 장황한 대화, 유도 질문, 기억의 왜곡이 새로운 오류원이 될 수 있다.
선택지를 없애도 질문 표현에서 발생하는 편향까지 없어지지는 않는다.

예를 들어 “정확한 분은 모르지만 저녁 먹고 목욕하기 전에 입술이 부었어요”라는 답변은
아직 어느 구간인지 결정하기에 부족하다. 사건의 시각을 더 기억하는지 확인할 수 있지만,
대답이 더 나오지 않으면 불확실 상태를 유지해야 한다.

### 3.2 선택지형의 강점도 보존해야 한다

- 범주를 잘 이해하고 시간을 기억하는 사용자에게는 클릭 한 번이 더 빠를 수 있다.
- 연구가 네 구간만 요구하면 더 자세한 시간의 실익이 작을 수 있다.
- 입력·코딩 규칙이 일정하고 추출 모델에 의한 오류가 적다.
- 타이핑·읽기·응답 부담을 줄일 수 있다.
- “약 1시간 뒤”처럼 명확한 답변에서는 개방형 재질문이 불필요하다.

Pew는 응답 선택지와 개방형 여부가 답변에 영향을 줄 수 있음을 설명한다.
또한 자체 온라인 조사 분석은 개방형 문항의 미응답 부담을 보여준다.
이 결과를 근거로 특정 임상 집단에서의 우열을 미리 단정하지 않는다.
[설문 문항 작성](https://www.pewresearch.org/writing-survey-questions/),
[개방형 문항의 미응답 분석](https://www.pewresearch.org/decoded/2021/10/14/why-do-some-open-ended-survey-questions-result-in-higher-item-nonresponse-rates-than-others/)

### 3.3 응답 형식과 재질문은 독립적인 요인이다

선택지형에도 명료화 질문을 붙일 수 있다. 개방형이어도 재질문을 금지할 수 있다.
이를 섞어 비교하면 효과의 원인을 분리하기 어렵다.

| 실험 조건 | 응답 형식 | 같은 유형 재질문 |
|---|---|---|
| A | 원문 선택지 | 불허 |
| B | 원문 선택지 | 허용 |
| C | 개방형 | 불허 |
| D | 개방형 | 허용 |

- A–B와 C–D: 재질문 효과.
- A–C와 B–D: 응답 형식 효과.
- 두 차이의 차이: 개방형에서 재질문의 가치가 더 커지는지.
- “개방형 → 필요한 경우 선택지 확인”은 별도의 혼합형 조건으로 후속 비교한다.

순수 개방형 실험에서는 후속 질문에 네 구간이나 양자택일 범주를 제시해 혼합형으로 바꾸지 않는다.
공통 평가에서는 모든 조건의 응답을 동일한 원문 범주·불확실 상태로 매핑한다.
선택지형에도 모름·해당 없음·정정 방법을 제공해 불리한 비교군을 만들지 않는다.

먼저 정책·종료 규칙을 통제해 형식 효과를 비교하고, 이후 각 조건에서 동일한 학습 예산으로
정책을 훈련해 최종 성능을 비교한다. 한 조건에서 학습한 정책만 다른 형식에 그대로 적용해 우열을 결론내리지 않는다.

### 3.4 평가 계획

- 주요 지표: 원문 범주 및 목표 판정의 정확성, 근거 부족 상태의 잘못된 조기 종료율.
- 보조 지표: 턴·토큰·소요 시간, 미응답·이탈, 정정 횟수, 응답 부담.
- 재질문 지표: 전후의 범주 오류·미확인 상태 변화, 유용한 확인 비율, 불필요한 반복 비율.
- 하위 집단: 명확한 기억, 애매한 시간, 경계값, 여러 반응 사건, 기억 불가, 상충된 응답.
- 단위: 환자 시나리오·전체 세션을 기준으로 비교하고, 같은 세션의 여러 턴을 독립 표본처럼 세지 않는다.

같은 사례와 조건을 대응시켜 비교하되, 사람 대상 반복 조사에서는 학습·기억 효과를 고려해
무작위 배정이나 순서 균형화를 설계한다. LLM simulator만으로 사람의 부담을 검증할 수는 없다.
재질문이 필요한 사례를 많이 넣은 합성 데이터와 실제 빈도를 반영한 데이터의 결과를 구분한다.

## 4. 대화 이력을 직접 읽는 LLM 정책

### 4.1 제안에 대한 판단

**이 연구의 주된 정책으로 검토할 만한 구조다.**
수작업으로 만든 특징 벡터가 누락할 수 있는 표현, 시점 변화, 불확실성을 대화 원문에서 읽을 수 있다.
그 이점이 실제로 발생하는지는 작은 MLP 정책을 비교군으로 남겨 검증한다.

입력과 출력은 다음과 같다.

```text
공개 프로필 + 현재 식품 + 실제 대화 이력
                    ↓ tokenize / chat template
4-bit 기반 LLM W0 (고정) + policy LoRA ΔW (학습)
                    ↓ 마지막 유효 위치의 hidden representation
          ├─ policy head: hidden_size → 7
          └─ value head:  hidden_size → 1
```

`policy head`는 7개 유형의 logits를 만드는 분류 형태의 층이지만,
PPO에서는 정답 action의 cross-entropy가 아니라 보상 기반 policy loss로 학습한다.
`value head`는 PPO actor–critic의 누적 보상 예측용이며 알레르기 확신도와 다르다.

기반 가중치는 frozen이지만 **LoRA가 활성화된 모델 전체의 동작은 학습에 따라 변한다.**
QLoRA는 양자화된 고정 기반 가중치를 통과해 LoRA 파라미터를 학습하는 방법이다.
기반 전체에 `no_grad()`를 씌운 학습 forward는 그 경로의 LoRA 학습도 막을 수 있다.
[QLoRA 원논문](https://arxiv.org/abs/2305.14314), [PEFT 양자화 학습](https://huggingface.co/docs/peft/developer_guides/quantization)

### 4.2 입력 이력과 recurrent의 의미

각 턴에서 누적 대화 토큰을 다시 입력하는 방식만으로 시작할 수 있다.
별도 RNN이나 에피소드 전체에 걸친 BPTT가 반드시 필요한 것은 아니다.
LLM의 최종 hidden representation을 읽는 것이 명시적인 사고 과정을 생성하는 것과 같지는 않다.

- 정책 readout 위치와 입력 지시문을 고정한다.
- padding 위치를 읽지 않도록 attention mask와 실제 입력 위치를 사용한다.
- 현재 질문·미래 응답을 정책의 이전 상태에 넣지 않는다.
- 이력 길이 한도·자르기 규칙을 학습과 배포에서 동일하게 적용하고 원본 기록은 보존한다.
- 사용자 발화를 지시문과 구분해 감싸고 정책 명령으로 실행하지 않는다.
- 생성된 가설은 환자가 말한 사실과 구분한다.

PPO 버퍼에는 토큰 입력·attention mask·action·old log probability·value·reward·종료 정보를 저장한다.
업데이트 때 같은 관찰 입력으로 현재 정책의 확률을 다시 계산해야 한다.
LoRA를 학습하는데 detached hidden vector만 저장해 재사용하면 backbone adapter의 표현 학습이 이루어지지 않는다.

### 4.3 구체적인 모델 후보

2026-09-15 공식 자료 확인 기준:

- `google/gemma-4-E4B-it` 모델을 확인했다. “E4B”는 단순 총 4B라는 뜻이 아니다.
  공식 카드에는 effective 4.5B, embedding 포함 8B로 기재되어 있어 메모리를 별도로 측정해야 한다.
  [Google 모델 카드](https://ai.google.dev/gemma/docs/core/model_card_4),
  [공식 가중치](https://huggingface.co/google/gemma-4-E4B-it)
- 사용자가 예로 든 `qwen4:4b`에 대응하는 공식 체크포인트는 이번 확인에서 찾지 못했다.
  확인 가능한 후보로 `Qwen/Qwen3.5-4B`가 있다. 이를 사용자 지정 모델로 자동 확정하지 않는다.
  [Qwen 공식 가중치](https://huggingface.co/Qwen/Qwen3.5-4B)

`gemma4:e4b` 같은 추론 서버 태그와 PyTorch 학습 체크포인트는 구분한다.
HTTP 생성 API만 호출해서는 hidden state에 head를 연결하거나 QLoRA 역전파를 할 수 없다.
정책은 가중치를 로컬 학습 코드에서 로드해야 한다.
모델별 텍스트 decoder 접근법, 양자화·LoRA 지원, 실제 메모리·속도는 아직 검증하지 않았다.

## 5. 정책과 질문 생성에 같은 backbone 사용

### 5.1 생성용 head를 유지한다

기존 vocabulary 크기의 `lm_head`를 7차원 층으로 교체하면 자연어 생성 경로를 잃는다.
**원래 lm_head를 유지하고 policy head와 value head를 병렬로 추가**한다.

정책 선택과 질문 생성은 입력이 다르므로 보통 두 번의 forward/generate가 필요하다.

1. 정책 입력: 프로필·현재 식품·대화 → action index.
2. 생성 입력: 프로필·대화·선택 action·실현된 skeleton·생성 지시 → 질문.

가중치를 공유한다고 두 작업의 forward가 자동으로 하나가 되지는 않는다.

### 5.2 같은 기반 가중치와 같은 학습 어댑터를 구분한다

| 변형 | 정책 | 질문 생성 | 의미 |
|---|---|---|---|
| 공유 기반 모델, 역할별 adapter 적용 | W0 + 학습 LoRA | 같은 W0, policy LoRA 비활성화 | 질문 생성 분포를 고정하고 질문 유형 정책을 학습 |
| 학습 adapter까지 완전 공유 | W0 + 학습 LoRA | W0 + 같은 학습 LoRA | 정책 업데이트가 질문 표현에도 영향을 줌 |

두 방식 모두 같은 기반 LLM을 사용한다. 다만 첫 방식은 **유효한 모델 가중치까지 동일한 방식은 아니다.**
사용자의 완전 공유 아이디어를 평가할 수 있도록 두 번째 방식도 실험 항목으로 남긴다.

첫 주 실험은 첫 방식을 권장한다. PEFT의 `disable_adapter()` 같은 기능으로
한 기반 모델을 유지하면서 생성·평가 때 policy adapter를 끌 수 있다.
[PEFT adapter 비활성화](https://huggingface.co/docs/peft/package_reference/peft_model#peft.PeftModel.disable_adapter)

생성 때 `torch.no_grad()`만 사용한다고 생성기가 고정되는 것은 아니다.
다른 loss로 공유 LoRA를 갱신하면 다음 턴의 생성도 달라진다.
`no_grad()`는 해당 호출의 gradient 기록을 제어한다.
[PyTorch autograd 설명](https://docs.pytorch.org/docs/stable/notes/autograd)

### 5.3 완전 공유에서 action-only PPO의 한계

완전 공유에서는 다음 분포가 함께 바뀐다.

```text
p(action, question | history)
    = policy(action | history)
      × generator(question | history, action)
```

7개 action의 log probability만으로 PPO를 업데이트하면 질문 토큰의 확률 변화는 목적함수에 반영되지 않는다.
파라미터에 의존하는 질문 생성 과정을 고정된 환경처럼 취급하는 근사다.
작동 여부는 실험할 수 있지만, 정확한 전체 joint policy gradient라고 주장해서는 안 된다.

가능한 후속 실험은 action과 질문 토큰의 log probability를 함께 다루는 학습,
별도 generation adapter와 보조 생성 loss, 역할별 학습 단계 분리다.
이는 token-level 학습·생성 품질 유지·PPO 확률비 처리까지 추가하므로 첫 action-only 실험보다 복잡하다.

질문 생성 품질·action 준수율·무관한 질문·언어 능력 유지도 측정해야 한다.
같은 문제는 학습 중인 adapter를 내부 판정·종료 평가에도 적용할 때 발생한다.
첫 실험은 그 평가 경로도 고정해 정책이 바뀔 때 평가 기준까지 함께 움직이지 않도록 한다.

## 6. state.py와 파일 책임

LLM이 대화 이력을 직접 인코딩하면 기존 제안의 **수작업 특징 벡터를 만드는 state.py는 필수가 아니다.**

그러나 실행에 필요한 상태는 남는다.

- 공개 프로필, 현재 food_id, 실제 messages
- pending action·질문, 질문 이력
- 내부 판정 결과와 근거
- 턴 수, 종료 상태·사유

첫 구현은 작은 dataclass를 `environment.py`에 두고,
정책 입력 직렬화·tokenization은 `model.py`에서 처리하는 안을 권장한다.
커지기 전부터 별도 state abstraction 모듈을 만들 필요는 없다.
최종 기록을 구조화하거나 평가에 필요한 사실을 추출하는 작업은 정책의 필수 입력 벡터와 별개다.

가상 사용자 파일명은 **user_simulator.py**로 정리한다.
[최신 파일 구조](research_architecture.md)에 반영했다.

## 7. 매 턴 내부 판정과 종료

### 7.1 내부 판정은 유용하지만 긴 사고문이 필수는 아니다

현재 가설을 계속 갱신하는 것은 합리적이다.
사용자에게 보여주는 질문과 별도로, **예측·관찰 근거·미확인 사항·종료 준비 여부**를 짧게 기록하면 된다.
이를 검증 가능한 중간 산출물로 취급하며, 모델의 실제 내부 사고 전체를 읽은 것으로 해석하지 않는다.

다음은 형식 예시다.

```json
{
  "food_id": "egg",
  "target_definition": "study_2015_current_immediate_type",
  "prediction": "undetermined",
  "evidence_turn_ids": ["user_2"],
  "missing_evidence": ["onset_time", "current_intake"],
  "contradictions": [],
  "ready_to_stop": false
}
```

`prediction`은 선택한 과제 정의에 따라 positive/negative/undetermined 등을 사용한다.
“우유 알레르기 같다”는 문자열만 비교하는 것보다 식품별 판정과 기준을 명시하는 것이 낫다.
D에 이미 의심 식품이 공개되어 있으므로 식품명 일치만 보상하면 질문 없이 맞힐 수 있다.
알레르기 없음·다중 식품·미확정 사례도 포함해야 한다.

내부 판정은 매 턴 실제 공개 기록을 기반으로 재평가한다.
이전 가설을 사용자 발언처럼 사실화하거나, 가설에 맞는 답을 유도하지 않는다.
기본 정책 입력은 원문 대화이며 내부 판정을 추가 입력으로 줄지는 별도 비교 실험으로 둘 수 있다.

### 7.2 정답 일치 즉시 종료의 문제

다음 규칙은 주 학습·배포 종료 규칙으로 권장하지 않는다.

```text
if 내부 예측 == 숨겨진 정답:
    종료 + 보상
else:
    대화 계속
```

이유:

1. 실제 사용자에게는 숨겨진 정답이 없으므로 같은 규칙을 실행할 수 없다.
2. 충분한 근거 없이 맞힌 예측도 즉시 성공 처리될 수 있다.
3. “계속된다”는 신호가 직전 예측이 틀렸음을 알려주는 정답 정보가 된다.
4. 가설을 번갈아 내는 전략이나 데이터의 다수 클래스 추측이 유리해질 수 있다.

정답을 아는 oracle 종료는 별도 비교군으로 둘 수 있지만,
실제 배포 가능한 결과와 구분해 보고한다. 근거 조건이 없으면 임상적 충분성의 상한도 아니다.

### 7.3 권장하는 실행 순서

```text
사용자 답변
  → 공개 기록만으로 내부 판정 갱신
  → 종료 준비 + 증거 기준 + 상충 여부 확인
      ├─ 계속: 다음 action 선택
      └─ 종료: 판정 확정
           → 학습에서만 정답·근거 기준과 비교
           → terminal reward
```

틀린 판정으로 종료했으면 실패 보상을 받고 그 episode를 끝낸다.
정답을 보고 같은 episode에서 다시 추측할 기회를 주지 않는다.

7개 질문 action을 유지하면 종료는 여전히 별도 규칙이다.
추후 종료 정책 자체를 학습하려면 별도 stop head 등 변경을 명시해야 한다.
그 head를 넣는다면 “학습되는 행동은 질문 유형 7개뿐”이라는 기존 정의도 수정해야 한다.

초기 평가기는 같은 기반 모델의 고정 경로를 사용할 수 있다.
하지만 같은 모델을 썼다는 사실이 독립적인 검증을 뜻하지는 않는다.
전문가 검토·보류 데이터로 잘못된 조기 종료를 별도로 확인한다.
문진의 내부 예측과 임상 확진도 구분한다.
[EAACI 진단 가이드라인](https://pubmed.ncbi.nlm.nih.gov/37815205/)

## 8. 지연 보상으로 학습할 수 있는가

### 8.1 가능하며 매 턴 보상은 필수 조건이 아니다

T개 질문 action이 있을 때 0부터 인덱싱하면:

```text
r_0 = ... = r_(T-2) = 0
r_(T-1) = R_terminal

G_t = gamma ** (T - 1 - t) * R_terminal
```

마지막 보상이 앞선 action들의 return에 포함된다.
PPO는 value와 advantage를 통해 정책을 업데이트할 수 있다.
이는 시간이 거슬러 사용자 문장에 미분하는 것이 아니라,
각 시점의 action log probability를 return/advantage로 가중해 학습하는 방식이다.
[PPO](https://arxiv.org/abs/1707.06347), [GAE](https://arxiv.org/abs/1506.02438)

다만 한 성공 trajectory만으로 어떤 질문이 유용했는지 정확히 식별해 주지는 않는다.
많은 trajectory에서 유용한 순서와 불필요한 반복의 차이를 학습해야 하므로 표본 효율과 분산이 과제다.

### 8.2 질문 효율을 보상에 반영한다

gamma=1이고 정답이면 항상 같은 +1만 주면, 3턴 성공과 20턴 성공이 같은 return을 갖는다.
단축이 목표라면 비용을 명시해야 한다.

첫 보상 실험으로 다음 두 조건을 제안한다.

- **순수 terminal:** 종료 시 판정 정확성·근거 충분성을 평가.
- **terminal + 비용:** 같은 terminal 평가에 턴 수 또는 시간 비용을 반영.

비용을 `R_terminal = quality - beta * T`처럼 마지막에 한 번 반영해도 지연 보상이다.
또는 매 턴 작은 비용을 주고 마지막에 성공·실패 보상을 줄 수 있다.
둘은 할인율에 따라 목적이 달라질 수 있으므로 같은 수식으로 취급하지 않는다.

정답 레이블 일치뿐 아니라 관찰 근거의 충분성도 terminal 평가에 넣는다.
잘못된 조기 종료, 모름을 음성으로 처리한 경우, 턴 한도에 걸린 경우를 구분한다.

### 8.3 내부 판정이 있어도 보상이 반드시 sparse인 것은 아니다

훈련에서만 매 턴 예측 분포를 정답과 비교하거나 검증된 근거 증가를 평가해 shaping reward를 만들 수 있다.
다만 자연어 confidence는 보정된 확률이 아니고, 학습되는 모델이 자신의 보상 기준까지 바꾸면 점수 조작이 생길 수 있다.

따라서 첫 실험은 **terminal 중심 보상 + 명확한 비용**으로 시작하고,
고정된 평가자의 중간 보상이 학습 효율을 높이는지 별도 ablation으로 확인하는 편을 제안한다.
내부 가설 생성, 실제 종료 판단, 정답을 사용하는 보상 계산은 서로 구분한다.

## 9. 실험을 단계적으로 구성하는 안

한 번에 모든 축을 바꾸면 효과를 해석하기 어렵다.

1. 고정된 정책·평가 조건에서 선택지/개방형 × 재질문 허용 여부를 비교한다.
2. 주 응답 형식에서 순차·무작위·MLP·LLM head-only·LLM QLoRA 정책을 비교한다.
3. 공유 기반 모델에서 생성 adapter 비활성화와 완전 공유를 비교한다.
4. terminal 보상, terminal+비용, 고정 평가자 shaping을 비교한다.
5. 실제 보호자·의료진 평가로 시뮬레이션 결과의 적용 가능성을 검증한다.

공통으로 scenario 단위 train/validation/test 분리, 동일한 평가 데이터·예산,
여러 seed, 질문 생성·평가 버전, action 준수율, 오류 유형별 결과를 기록한다.
LLM 정책이 더 느리고 많은 메모리를 요구할 수 있으므로 정확도뿐 아니라 전체 문진 시간·GPU 메모리도 비교한다.

## 10. 현재 제안의 요약과 미확정 사항

추천 출발점:

- 7개 질문 유형, 재질문 허용.
- 개방형+재질문을 주 연구 조건으로 검토하되 강한 선택지형 비교군 유지.
- 양자화된 고정 기반 LLM + policy LoRA + 7차원 policy head + 1차원 value head.
- 같은 기반 LLM으로 질문 생성·내부 판정을 수행하되, 첫 실험에서는 policy adapter를 비활성화.
- 대화 이력을 직접 입력하며 별도 수작업 state encoder는 두지 않음.
